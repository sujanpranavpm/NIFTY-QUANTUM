## 0. How to read this specification

Each dataset entry states, in fixed order:

- **Fields** — the individual columns the research layer actually consumes (or would consume).
- **Purpose** — why it is required.
- **Consumers** — the specific strategies/modules that read it (verified from code).
- **Resolution** — the minimum bar/tick granularity.
- **Minimum history** — how far back it must reach to be useful.
- **Accuracy** — verification bar (observed vs derived vs estimated).
- **Update frequency** — how often it must be refreshed.
- **Sourced / Calculated** — whether it must come from an external observation or is computed in-repo.
- **Class** — one of the seven requirement classes in §2.
- **Dependencies** — other datasets it needs before it can be used.
- **If-missing** — the concrete research consequence.

Three labels are used throughout and are **never merged**:

- **[OBSERVED]** — a value measured from a market/print (an exchange file, a traded price, a
  provider bar). This is real market data.
- **[DERIVED]** — a value computed by this repo *from observed inputs only* (a resample, a
  Black-Scholes inversion, an aggregate, a ratio). It is *not* an additional market observation and
  must always carry its derivation provenance.
- **[SIMULATED]** — a value produced by running a **strategy + execution + cost model over**
  observed prices (a backtest trade's net ₹ P&L, a portfolio equity curve, a bootstrap sample).
  It is a *model output*, contingent on the signal rule, fill assumption and cost schedule — and is
  **never** an observed market return.

**Live-trading returns are a fourth, separate category** (real fills under real liquidity). None exist
in this project, and none are implied by a backtest.

### The Monte Carlo clarification (applies to §G)

A run of **10,000 Monte Carlo / bootstrap iterations is 10,000 computational repetitions of a
resampling of a *finite* [SIMULATED] backtest set — not 10,000 independent historical observations,
and not 10,000 observed market returns.** The data requirement is the **simulated trade-level and
daily-return series** that the backtest produces from the finite observed price history; the iteration
count adds zero market information. No dataset on disk "supplies 10,000 samples"; the sampler
manufactures repetitions from the real (small) historical sample, and the confidence a result carries
is bounded by (a) that real observed-price sample size and (b) the strategy/execution assumptions that
turned prices into trades — never by the iteration count.

## 2. The seven requirement classes

Classification used for every dataset below (`Class` field):

1. **[C1] Mandatory — current NIFTY options research.** Without it the five Tier-1 candidates
   cannot be run at all.
2. **[C2] Mandatory — future options research.** Needed the moment a new options capability
   (IV-aware, spread, hedged, or short-option) is attempted.
3. **[C3] Mandatory — cash-equity research.** Needed for the 18 equity strategies and a real
   full-universe run.
4. **[C4] Mandatory — strict financial validation.** Gates whether a number may be published as a
   verified financial fact (`readiness.py` fail-closed gates + cost verification flags).
5. **[C5] Mandatory — realistic execution simulation.** Needed for fills to reflect tradable
   reality (spread, depth, liquidity) rather than an idealised mid.
6. **[C6] Required — advanced statistical / Monte Carlo research.** Feeds bootstrap/walk-forward/
   regime-conditioned inference; its absence caps statistical confidence but does not stop a
   point backtest.
7. **[C7] Optional — supplementary market information.** Enriches analysis; not required by any
   current code path.

Priority shorthand: **P0** = class C1; **P1** = C4/C5 (correctness & realism); **P2** = C6/C2/C3
(capability expansion); **P3** = C7.

## A. UNDERLYING MARKET DATA

### A1. NIFTY spot index — daily OHLC · **[OBSERVED]**
- **Fields:** trading_day, open, high, low, close. *(No bid/ask; an index has no traded volume.)*
- **Purpose:** reference level for strike moneyness/ATM selection, DTE ruler, signal-side close.
- **Consumers:** `options/selection.py` (ATM = round(spot/interval)), contract eligibility; every
  option-buying candidate.
- **Resolution:** daily (1d). **Min history:** ≥5 yrs spanning multiple volatility regimes.
- **Accuracy:** must reconcile to the derived intraday close; ±1 tick.
- **Update:** daily. **Sourced.** **Class C1 (P0).** **Deps:** trading calendar (A5).
- **If-missing:** no moneyness anchor → no strike selection → no option entry. *Available: derivable
  from the daily aggregation of the 1-minute index (A2).*

### A2. NIFTY spot index — 1-minute intraday OHLC · **[OBSERVED]**
- **Fields:** timestamp (open-labelled), open, high, low, close, volume (=0), trading_day, symbol.
- **Purpose:** the underlying time series the daily signal is computed from *and* resampled to
  intraday bars for any intraday option signalling; session/DTE ruler.
- **Consumers:** `derivatives/candles.py` resample grid; the index-signal path in the adapter.
- **Resolution:** 1m (→5m/15m derived). **Min history:** co-extensive with the option archive.
- **Accuracy:** session-bounded 09:15–15:30; `15:30` is a closing print, not a candle.
- **Update:** daily append. **Sourced.** **Class C1 (P0).** **Deps:** A5, timestamps convention.
- **If-missing:** cannot align a daily signal to a next-bar option entry. *Available: 1m index cached.*

### A3. Index futures (NIFTY futures) OHLC · **[OBSERVED]**
- **Fields:** underlying, expiry, OHLCV, OI.
- **Purpose:** only if a futures-basis / cost-of-carry study or the `orders_20` futures strategy is
  attempted; a futures close is *not* a substitute for the spot index in ATM selection.
- **Consumers:** `orders_20_futures_donchian` (registered, **`applicable=False`, not adapted**).
- **Resolution:** daily minimum, intraday if `orders_20` is ever run. **Sourced.**
- **Class C3/C7 (P2/P3).** **Deps:** futures contract specs, margin (F-series reference).
- **If-missing:** `orders_20` cannot run (already excluded). Does **not** block Tier-1 options.

### A4. Historical volatility inputs · **[DERIVED]**
- **Fields:** realised-vol series (e.g. 20d close-to-close σ), windowed from A1/A2.
- **Purpose:** regime conditioning, position sizing, and the *only* vol signal available without IV.
- **Consumers:** `validation/regime.py` (regime_ma_bars), sizing assumptions.
- **Resolution:** daily. **Min history:** ≥5 yrs. **Accuracy:** derived; label as derived.
- **Calculated in-repo.** **Class C6 (P2).** **Deps:** A1.
- **If-missing:** only affects vol-conditioned analysis, not a point backtest.

### A5. Trading sessions & market holidays · **[OBSERVED]**
- **Fields:** trading_day (boolean/date list), session open/close times.
- **Purpose:** the calendar against which DTE, next-bar entry, session completeness and walk-forward
  folds are measured; holiday-shift rule (expiry can move on a holiday).
- **Consumers:** `derivatives/timestamps.py`, `candles.py` session rules, `coverage_registry.py`,
  `selection.py` DTE ruler, `walkforward.py`.
- **Resolution:** per-date. **Min history:** full archive span (2021→now) **and forward** (future
  expiries). **Accuracy:** authoritative; must come from the exchange, never assumed.
- **Update:** each session + calendar publish. **Sourced.** **Class C1 (P0).**
- **If-missing:** DTE and next-bar mapping become guesswork. *Currently sourced only from the
  bhavcopy reachability arbiter, which starts 2024-01-02 → **2021-2023 sessions are single-source**.*

## B. OPTIONS DATA

### B1. CE/PE option premium bars — 1m / 5m / 15m / daily · **[OBSERVED (1m) → DERIVED (5m/15m/daily)]**
- **Fields:** timestamp, open, high, low, close, volume, open_interest, trading_day, symbol, strike,
  option_type (CE/PE), expiry. Derived candles add audit columns: `n_minute_buckets`,
  `last_minute_label`, `contains_closing_print`, `closing_print`, `closing_print_volume`,
  `oi_is_last_minute_observation`, `session_verdict`, `candle_open`.
- **Purpose:** the traded price the entry/stop/target/exit fills execute at; the entire option P&L.
- **Consumers:** `options/data.py`, `options/bars.py`, `engine/options_execution.py`, all Tier-1 candidates.
- **Resolution:** 1m observed; 5m/15m derived by the generator (`GRID_MINUTES`); daily derived.
  `readiness.py` gates **1m/5m/15m** — a **60m dataset is not produced and not gated**.
- **Min history:** every traded expiry across regimes. **Accuracy:** close reconciles to exchange
  `LastPric` (100% for 2024+ under arbiter; pre-2024 unverifiable).
- **Update:** daily. **Sourced (1m) + Calculated (5m/15m).** **Class C1 (P0).** **Deps:** A5, B-tick, B-lot.
- **If-missing:** no premium price → no option trade at all. *Available: dense weekly/monthly expiries
  cached; pre-2024 present-but-unarbitrated.*

### B2. Option volume · **[OBSERVED]**
- **Fields:** per-bar volume (share-equivalents), plus official daily `TtlTradgVol` (contracts).
- **Purpose:** liquidity evidence behind a fill; the (currently defective) exit-liquidity gate.
- **Consumers:** `derivatives/units.py`, `engine/options_execution.py` liquidity check.
- **Resolution:** bar + daily. **Accuracy:** provider volume is **share-equivalents** (contracts × lot);
  official `TtlTradgVol` is **contracts** — never merge; convert via the effective lot.
- **Class C1/C5 (P0/P1).** **Deps:** B7 (lot).
- **If-missing / mis-scaled:** the liquidity gate `min_exit_volume=1.0` is **1 share-equivalent and
  rejects nothing** (known pitfall) — volume is present but *not yet usable as a real filter*.

### B3. Option open interest · **[OBSERVED, but not one continuous series]**
- **Fields:** per-bar OI (share-equivalents until 2024-12-31; ÷100-scale from 2025-01-01),
  official daily `OpnIntrst` (share-equivalents), `ChngInOpnIntrst`.
- **Purpose:** positioning/PCR inputs; contract activity confirmation.
- **Consumers:** `units.py` (×100 correction labelled `estimated`), any future PCR feature.
- **Accuracy:** **≤2024-12-31 continuous to official; from 2025-01-01 a ×100 break with
  `estimated=True`; only ~67.5% of contract-days verifiable**; 33.6%→22.4% OI availability
  deterioration through 2026.
- **Class C2/C7 (P2/P3).** **Deps:** B7.
- **If-missing:** OI-based features restricted to verified observations only; never use raw archive OI
  as an intraday maximum.

### B4. Strike & expiry identity · **[OBSERVED]**
- **Fields:** strike, option_type, expiry (XpryDt + FininstrmActlXpryDt on the official side).
- **Purpose:** contract identity for selection and reconciliation; the ATM ladder.
- **Consumers:** `selection.py`, `coverage_registry.py`, `reference.py`.
- **Class C1 (P0).** **If-missing:** cannot name a tradable contract.

### B5. Historical contract universe (which contracts existed) · **[OBSERVED]**
- **Fields:** per-day listed (expiry, strike, type) set.
- **Purpose:** defines what *should* have data (the "expected" side of completeness); a universe must
  be derived from the archive/exchange, not assumed.
- **Consumers:** `coverage_registry.py` expected-vs-observed; `selection.py` eligibility.
- **Accuracy:** **official arbiter only 2024-01-02+**; pre-2024 universe is UNKNOWN (single-source).
- **Class C1/C4 (P0/P1).** **If-missing:** completeness cannot be distinguished from sparsity; silent
  skips possible (the gates forbid this).

### B6. Settlement & expiry prices · **[OBSERVED]**
- **Fields:** official `SttlmPric`, expiry-day close, `LastPric`.
- **Purpose:** correct expiry settlement value for a held option; the arbiter for a day's O/H/L/last.
- **Consumers:** *intended* expiry settlement; today `options_execution.py` settles at the **last
  premium-bar close, not the official `SttlmPric`** — this is a realism gap, not a data gap (the value
  exists for 2024+).
- **Class C4/C5 (P1).** **If-missing:** settlement P&L cannot be validated against the exchange.

### B7. Historical lot sizes · **[OBSERVED 2024+, DERIVED/estimated pre-2024]**
- **Fields:** effective_from/to, lot value, `estimated`, `provenance`; official `NewBrdLotQty` (per-row).
- **Purpose:** converts share-equivalents↔contracts and sizes P&L (₹/point = lot).
- **Consumers:** `reference.py` `LotTable`, `units.py` (`contract_lot_for_pnl` raises `AmbiguousLotError`
  on mixed-lot days — 61 such days), execution sizing.
- **Accuracy:** regime 75→50→25→75→65; **pre-2024-01-02 `estimated=True` ("NO official arbiter")**.
- **Class C1/C4 (P0/P1).** **If-missing:** contract count and ₹ P&L are wrong by the lot factor.

### B8. Tick sizes · **[OBSERVED]**
- **Fields:** effective-dated premium tick (₹0.05 traded throughout; settlement slab 0.10 from 2026-08-03).
- **Purpose:** fill realism, price-grid validation.
- **Consumers:** `reference.py`, price-grid checks. **Class C4/C5 (P1).**

### B9. Strike intervals · **[OBSERVED]**
- **Fields:** effective-dated grid (1000 → 500 → 50 across 2026).
- **Purpose:** the ATM rounding and the strike ladder step in `selection.py`.
- **Consumers:** `selection.py` (as-of trade date). **Class C1 (P0).**
- **If-missing / constant:** wrong ATM strike; must be read as-of, never a single constant.

### B10. Historical bid/ask prices · **[NOT AVAILABLE]**
- **Fields:** would be bid, ask (time-stamped). **Consumers:** would be `options_execution.py` for a

- **Class C5 (P1).** **Reality:** *no permitted ₹0 source carries historical bid/ask* (P1 finding).
- **If-missing (permanent under ₹0):** fills are modelled at bar OHLC + assumed slippage bps; a real

### B11. Bid-ask spreads · **[DERIVED from B10 — NOT AVAILABLE]**
- **Class C5 (P1).** Depends entirely on B10; not obtainable.

### B12. Order-book depth (multi-level) · **[NOT AVAILABLE]**

## C. VOLATILITY AND DERIVATIVES

### C1. India VIX · **[OBSERVED — NOT PRESENT]**
- **Fields:** daily VIX open/high/low/close (the exchange's composite index-level volatility benchmark).
- **Purpose:** a *market-observed* index volatility gauge for **VIX-conditioned regime analysis**, position
  sizing, and vol-of-vol studies. Missing India VIX prevents India-VIX-conditioned regime analysis.
  **It is NOT an input to Black-Scholes implied-volatility inversion and is NOT mathematically required to
  derive an individual option contract's implied volatility** — those are distinct concepts (see C2).
- **Consumers:** none currently (no code reads VIX — verified by negative grep).
- **Class C6/C7 (P2/P3).** **Reality & provenance:** not fetched today. However, **India VIX is published
  historically by NSE free of charge on its official website**, identifying it as an obtainable candidate for
  a later authorised source-discovery milestone (P2.2.8). It is not searched or fetched in this milestone.
  Its absence blocks only VIX-*conditioned regime* work, not individual contract IV estimation.

### C2. Historical implied volatility · **[DERIVED / ESTIMATED — not stored]**
- **Fields:** per-contract IV. **Purpose:** IV-aware strike selection, volatility-surface research.
- **Consumers:** would be `selection.py`, any vol-aware strategy. **Class C2 (P2).**
- **Derivation mechanism:** contract implied volatility can, in principle, be estimated by inverting an
  option-pricing model (such as Black-Scholes) using observed option premium (B1), underlying spot (A1),
  strike, and time to expiry (B4), alongside a defensible **risk-free rate input (C4)** and an index
  **dividend/yield assumption (C5)**.
- **Critical distinctions & limitations:**
  1. **India VIX (C1) is NOT an input to this inversion.** Contract IV reflects *that individual contract's own
     market premium*, strike, and maturity, not the index-level VIX composite. Index VIX and contract-level IV
     must not be conflated.
  2. **Model-derived estimates, not observed data:** any calculated IV and resulting Greeks (C3) are
     **MODEL-DERIVED / ESTIMATED outputs**, not observed exchange quotes or provider prints. Model, inputs,
     pricing conventions, timestamp, and mathematical limitations must be recorded separately from observed data (Rule H5).
  3. **Not equivalent to an observed volatility surface:** model-derived single-contract IV estimates do not
     constitute an observed market volatility surface, cannot capture market microstructure or true supply/demand
     skews, and must not be assumed suitable for every IV-aware strategy.
  4. **Two distinct gaps, kept distinct:** (i) missing **observed contract IV** (exchange-disseminated contract IV)
     prevents research that specifically requires actual historical IV observations; (ii) missing **India VIX**
     blocks only *India-VIX-conditioned regime* research.
- **If-missing (observed IV):** IV-aware / delta-targeted strategy development is **explicitly out of scope**
  on confirmed data (design §2); current selection uses only observable spot/strike/expiry/premium/volume/OI.

### C3. Historical Greeks · **[DERIVED / ESTIMATED — not stored]**
- **Fields:** delta, gamma, theta, vega per contract. **Class C2 (P2).**
- **Derivation:** computed from the same pricing model and inputs as C2; **model-derived estimates, never
  observed market data.** If-missing: hedged, delta-neutral, or short-premium strategies cannot be developed.

### C4. Risk-free interest rate · **[OBSERVED — NOT PRESENT]**
- **Fields:** date, rate (e.g. 91-day / 182-day T-bill cut-off yield, MIBOR, or policy repo rate).
- **Purpose:** required parameter input to C2/C3 option-pricing model inversion; a pricing parameter, not a signal.
- **Reality:** `config.py` carries **no risk-free rate**; `analytics.metrics.sharpe_ratio(..., risk_free=0.0)`
  defaults to zero. **Class C2/C4 (P2).**
- **Candidate free official sources (for later discovery):** official sovereign benchmark yields (e.g. 91-day
  Treasury Bill cut-offs) are published historically by the Reserve Bank of India (RBI) and Financial Benchmarks
  India Pvt Ltd (FBIL) / CCIL. These are identified as candidate sources for a later authorised milestone (P2.2.8);
  no search or fetch is conducted here.
- **If-missing:** derived IV/Greeks cannot be calculated without assuming an arbitrary constant rate; Sharpe
  remains excess-over-0 (documented, not a data blocker for point backtesting).

### C5. Dividend assumptions (index-level) · **[OBSERVED/ASSUMED — NOT PRESENT]**
- **Fields:** index dividend yield / cash dividend schedule (for forward pricing of options near expiry).
- **Purpose:** required parameter input to C2/C3 Black-Scholes European index option pricing model inversion.
- **Class C2 (P2).** Not modelled today.
- **Candidate free official sources (for later discovery):** historical daily NIFTY 50 dividend yield series
  are published by NSE Indices in index statistics releases. Identified as candidate sources for a later
  authorised milestone (P2.2.8); no search or fetch is conducted here.
- **If-missing:** pricing model inversion must rely on an assumed dividend yield or zero-dividend proxy.

### C6. Derived IV / Greeks — labelled distinctly · **[DERIVED / ESTIMATED]**
- **Class C2 (P2).** Governance rule: any derived vol/Greek column must sit in a **separate store from
  [OBSERVED] fields** and record derivation model, parameter inputs, timestamp, and conventions, ensuring no
  reader or consumer can mistake a model-derived estimate for an exchange-observed datum.

   option premium bars B1, settlement prices B6) are **[OBSERVED]**, subject to provenance and quality checks.
2. **Historical backtest trade P&L and returns (G1)** are **[SIMULATED] / [DERIVED]** outputs calculated from
   observed market data combined with strategy signal rules, execution/fill assumptions, position sizing,
   and effective-dated cost schedules. They are never observed market returns.
3. **Daily portfolio returns and equity series (G2)** produced by a backtest run are likewise **[SIMULATED] / [DERIVED]**
   model outputs.
4. **Actual live-trading fills and realised account returns**, if they ever become available in a future production
   system, represent a distinct fourth category. No such records exist in this project today, and none must be
   implied to exist.
5. **Monte Carlo resampling:** the simulation engine resamples a finite set of backtest-generated outcomes (G1/G2),
   not raw observed market returns. 10,000 bootstrap iterations do not create 10,000 independent historical observations.)*

**Rule:** the statistical toolkit bootstraps **the finite set of *simulated* trade and daily portfolio returns
generated by the backtest from observed prices**; the simulation engine resamples these backtest-generated outcomes,
not raw observed market returns. The number of bootstrap iterations (e.g. 10,000) is a *numerical precision* knob,
not a *market data* multiplier — running 10,000 iterations does not create 10,000 independent historical observations.
The true statistical confidence is bounded strictly by (a) **the count of independent historical observed price-days
and out-of-sample events**, and (b) the validity of the strategy, execution, and cost assumptions that produced the
trades. Adding more observed market history (dense multi-week option expiries, full-universe equity data) — not more
computational iterations, and never misclassifying simulated P&L as observed market returns — is the only valid way to
raise empirical confidence. **Actual live-trading fills and realised account returns, if they ever exist, are a separate
category and do not exist now.**

## H. Cross-cutting governance requirements (not "data", but conditions on data)

- **H1 Effective-dated reads.** Lot/tick/strike/cadence/OI-scale **must** be resolved **as-of trade date**
  from the `EffectiveParameter` stores, never a single constant (verified convention across the layer). — C4.
- **H2 Estimated-vs-verified flags.** Reference rows carry `estimated` and `provenance`; a pre-2024-10 option
  cost row or a pre-2024 lot/OI value may be *simulated* but is reported as an assumption and is
  **excluded from strict financial validation** (`readiness.py` fail-closed). — C4.
- **H3 No silent skips / no fabrication.** Every expected (expiry, day, contract) key must be present or carry
  an explicit missing reason (`assert_no_silent_skip`); unverifiable sessions are **rejected, never guessed**;
  empty intervals are **not filled**. — C1/C4.
- **H4 Unit discipline.** Provider volume/OI are share-equivalents; official `TtlTradgVol`=contracts,
  `OpnIntrst`=share-equivalents; **never merge providers into one series**. — C1/C4.
- **H5 Derived labelling.** Any IV/Greek/realised-vol/PCR column lives in a **separate derived store** with
  inputs + timestamp recorded; never presented as observed. — C2.

## I. What this specification deliberately does NOT claim

- It does **not** claim any dataset is complete because current quality checks pass — coverage is audited
  separately against the actual files.
- It does **not** invent missing fields or assert that bid/ask, order-book depth, observed IV/Greeks,
  India VIX, participant data, macro, or point-in-time constituents *can be reconstructed accurately*.
  Where they are absent under ₹0, they are recorded as absent.
- It does **not** authorise downloading, provider discovery, accounts, paid services, strategy/exit changes,
  optimisation, backtest reruns, holdout access, or a Monte Carlo implementation. Those are separate,
  later milestones pending review.
