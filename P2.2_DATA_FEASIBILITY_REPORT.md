# P2.2.2 — Data Feasibility Report (NIFTY Options Buying Research)

Date: 2026-11-06 · Baseline commit: `03a5d27` (clean) · Budget: ₹0 · Companion:
`P2.2_OPTIONS_ADAPTATION_DESIGN.md`, `P2.2_BACKTESTING_METHODOLOGY.md`.

Scope: establish, from the **actual files on disk**, what a NIFTY CE/PE option-buying
backtest can and cannot be built on today. Nothing here assumes data exists because a
strategy requires it. Every number below was measured by reading the repository in this
session (probe over `data/raw/p1_sample`, `data/derived/candles`, `data/reference`).

Legend used throughout:
* **[FACT]** — measured/verified from files in this repo.
* **[ASSUMPTION]** — a modelling choice that is *not* settled by the data and must be
  declared, not silently inherited.
* **[LIMITATION]** — a gap that blocks or bounds research; carried honestly, not papered over.

---

## 0. Headline feasibility verdict

> A NIFTY option-buying backtest is **structurally feasible** (index signals, option
> premium bars, an options execution engine, an effective-dated cost schedule and a full
> validation toolkit all exist) but **statistically starved**: option premium candles
> exist on only **167 trading days** — almost all inside the final ≤2 weeks of **22 of the
> provider's 267** sampled weekly expiries — and only **158** of those days also carry index
> intraday; excluding expiry-day entries leaves **143 eligible entry-days**. Any
> trade-count / significance requirement in `P2.2_BACKTESTING_METHODOLOGY.md` will, on
> current data, most likely return **"insufficient evidence"**, which is a legitimate
> outcome — not a threshold to tune away. **[FACT]** + **[LIMITATION]**

### 1.2 NIFTY option premium data

**Raw** — `data/raw/p1_sample/options__NIFTY__<expiry>.parquet`, **one file per expiry**,
holding *all* strikes and both CE/PE inside. Measured schema: `timestamp, open, high, low,
close, volume, open_interest, trading_day, symbol, strike, option_type, expiry` (1-minute
premium bars). Example, the 2024-12-26 expiry file: **476,829 rows, 133 strikes, CE
256,641 / PE 220,188 rows**, life 2024-10-28 → 2024-12-26. **[FACT]**

**Derived** — `data/derived/candles/{1m,5m,15m}__NIFTY__<expiry>.parquet`, generated by
`scripts/_p2_generate_candles.py`. Three resolutions × 23 expiry files = 69 files. **[FACT]**

**Archive vs cache reconciliation (added in P2.2.2.1).** **[FACT]** The *provider* archive holds
**267 NIFTY expiry files** (`DATA_SOURCE_REGISTER.md` §1, `options/NIFTY/{EXPIRY}.parquet`,
~890 MB); this repo deliberately caches only **23**, of which **22 are usable** (2026-08-04 is an
empty-schema stub). So the dataset is a **~8% sample, not a complete history** — every count below
describes the sample, never the market. Totals over the 22 usable files: **4,441 distinct
contracts** (expiry×strike×type) across **27,636 contract-days**. The **official NSE arbiter only
reaches 2024-01-02 → 2026-11-03**, so pre-2024 lot/tick/OI values are `estimated`.
**[FACT]** Provider & derived `volume` is **share-equivalents (contracts × board lot)**, not
contracts (see `derivatives/units.py`; conserved 1m→5m→15m by the generator).

### 3.1 Time-to-expiry *at entry* and period split (added in P2.2.2.1)

**[FACT]** Measuring days-to-expiry on the **entry session (D+1)**, not the signal day, the 174
option file-days distribute as (trading-day DTE → count): `0→22, 1→19, 2→19, 3→18, 4→18, 5→17,
6→16, 7→13, 8→9, ≥9→15`; **median calendar DTE ≈ 6 days**. The **22 expiry-day (DTE=0) file-days
are excluded from the primary experiment**, leaving **143 index-overlap entry-days with DTE≥1**.
This quantifies that the sample is **short-DTE / theta-heavy**. **[FACT]**

**[FACT]** Splitting the 158 overlap days across the methodology periods: Development (2021-05→

i.e. the **holdout holds only ~32 opportunity days**, which cannot reach the trade-count floors
(see `P2.2_BACKTESTING_METHODOLOGY.md` §4). **[LIMITATION]**

## 4. Missing data & incomplete sessions

* **[FACT]** Option candles exist on **167 distinct trading days** in total (union over the
  22 files). Days per expiry are short and non-contiguous.
* **[FACT]** **9 of those 167 option days have no matching index intraday** (first/edge days);
  **1,104 of the 1,262 index days have no option candles at all**. The usable joint surface is
  **158 trading days**.
* **[FACT]** Timestamp convention is **open-labelled**: a bar stamped `T` covers `[T, T+1)`;
  the `15:30` bar is the closing/settlement print, not a minute (`derivatives/timestamps.py`,
  evidence `logs/m4_terminal_candle.txt`). Session 09:15–15:30 = **376 minutes**.
* **[FACT]** Session-quality is *classified, not assumed*: `classify_session` returns
  `STRICT_OK` / `NO_CLOSING_PRINT` / `AMBIGUOUS_OUT_OF_SESSION` etc. Blocks with stray labels
  past 15:30 (observed in Jan–Mar 2025 and on 2025-08-01) are **rejected**, not guessed.
* **[FACT]** Duplicate (contract×timestamp) rows are surfaced by `duplicate_timestamps` and
  must be excluded, not silently de-duplicated.
* **[FACT]** Open-interest units **break scale at 2025-01-01** (`units.py`: share-equivalent →
  one-hundredth share-equivalent, ×100), and lot values before 2024-01-02 are `estimated`
  ("NO official arbiter"). OI/PnL sizing must use the effective-dated `ParameterStore`, not a
  constant.
* **[FACT]** Official EOD OI is joined by `attach_official_eod` with an explicit
  `assert_no_eod_leakage` guard — the EOD print is same-day-settlement info and is quarantined
  from intraday decisioning.

## 5. Can signal timestamps be reliably aligned to option candles?

**Yes, for a daily-signal design — and this is exactly the Tier-1 case.** **[FACT]**

* Both the index and option series carry the same `trading_day` and IST open-labelled
  timestamps, so a signal computed **after the close of day D** maps deterministically to the
  **option bar at D+1 open (09:15)** — the `OptionsExecutionEngine` `signal_index+1` next-bar
  rule. No same-instant matching is needed.
* For any *intraday* option signalling, the raw **1m index can be resampled to the same
  5m/15m left-edge grid** the option candles use (buckets at :15/:30/:45/:00), so alignment is
  achievable — **[ASSUMPTION]** that index and option share the same verified open-label
  convention (the option side is proven; the index raw file follows the same provider stamping
  but has not been independently session-classified). Flagged, not assumed away.
* **[LIMITATION]** On any of the **158** joint days lacking a STRICT_OK option session, or
  the 9 option days lacking index intraday, no aligned entry exists — the trade is simply not
  taken (fail-closed), never fabricated.

## 6. Data-eligibility rules the methodology will enforce

Built directly on existing gates (no new code implied):

1. Only (contract-day) records the **coverage registry** marks non-missing and non-inactive
   are eligible; `assert_no_silent_skip()` must pass — every expected key is either present or
   has an *explicit* missing reason. **[FACT]** API exists.
2. Only `STRICT_OK` (or explicitly-accepted `NO_CLOSING_PRINT`) sessions may generate fills;
   anything `AMBIGUOUS_*` is excluded. **[FACT]** API exists.
3. A bar flagged `available=False` forbids any fill inside it (`OptionBar` invariant; expiry on
   such a bar → `UNRESOLVED`). **[FACT]** API exists.
4. Lot/tick/strike/expiry-cadence/OI-scale are resolved **as-of trade date** from the
   `EffectiveParameter` stores; `estimated=True` lots (pre-2024) are usable for *simulation* but
   must be reported as an assumption. **[FACT]** API + flags exist.

## 7. Confirmed facts vs assumptions vs unresolved limitations

**Confirmed facts**
* 1m NIFTY index (1,262 days) and 1m/5m/15m option premium bars for 22 usable expiries exist;
  open-labelled convention; full reference-parameter and coverage machinery present; an options
  execution + cost engine is already implemented.

**Declared assumptions**
* Index 1m shares the open-label convention when resampled to 5m/15m (untested for the index).
* `estimated` lot/tick regime values used where no official arbiter existed (pre-2024).
* Selecting the *nearest* listed expiry as the tradable contract (an eligibility choice, not a
  data fact) — see the adaptation design.

**Unresolved limitations (research-bounding)**
* **[LIMITATION]** Only **158** joint index+option trading days, concentrated in ≤2-week,
  short-DTE windows across a *sampled* set of expiries — cannot support a walk-forward with
  many OOS trades or robust per-regime statistics.
* **[LIMITATION]** No derived index candle set yet (raw 1m only).
* **[LIMITATION]** Option **cost** schedule is not fully verified: 2 slab-era `exchange_txn`
  rows remain `estimated`, so the readiness gate `transaction_costs_verified` is **fail-closed**
  and results are "modelling-only", never strict-financial (see cost section of the adaptation
  design).
* **[LIMITATION]** No point-in-time constituents/universe history; irrelevant to an *index-
  direction* option study but blocks `orders_17`-style designs.
* **[LIMITATION]** No historical implied-volatility or Greek surface is stored; therefore
  *IV-aware* or *delta-targeted* strike selection **cannot** be built from confirmed data and is
  explicitly out of scope (see adaptation design §2, "no future/unavailable Greeks").

## 8. Feasibility conclusion for the five Tier-1 candidates

| Candidate | Needs | Available now? | Consequence |
|-----------|-------|----------------|-------------|
| orders_12, 01, 18, 05, 07 | daily NIFTY direction | **[FACT]** index 1m/daily | Signal side is feasible today. |
| all five | option premium entry/exit + cost | **[FACT]** engine + schedule exist | Execution/cost side is feasible today (modelling-grade). |
| all five | enough *independent* trades for significance | **[LIMITATION]** ~158 days, short windows | Expect "insufficient evidence"; design must **not** lower thresholds to pass. |
| strike/expiry selection needing IV/Greeks | vol surface | **[FACT]** absent | Selection must use only observable spot/strike/expiry/premium/volume/OI. |

> **Verdict:** build the framework to be **correct and honest on a tiny sample**, report
> trade counts and confidence intervals, and let "insufficient evidence" stand as a valid
> result. The next task is *design*, not *implementation* — no strategy is modified here.
