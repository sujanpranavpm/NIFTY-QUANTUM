## 3. Architecture implemented

Provider-independent by construction: `service.py` talks to `MarketDataProvider`
(`providers/base.py`); nothing in the research stack or the ingestion layer imports
Upstox. A second provider only needs to implement the base protocol.

```
python -m nifty_quant.market_data collect
        |
   service.py ...... orchestration, exit codes, status views
        |
        +-- providers/base.py ....... MarketDataProvider protocol, modes, limits,
        |                            MarketStatusSnapshot, capability declarations
        +-- providers/upstox.py ..... RestClient + UpstoxProvider (all HTTP)
        +-- instruments.py .......... InstrumentDiscovery -> InstrumentUniverse
        +-- session.py .............. INSTRUMENT-INDEPENDENT session clock & trading days
        +-- websocket.py ............ WebSocketManager (connect, subscribe, resubscribe,
        |                            heartbeat, backoff, graceful shutdown)
        +-- proto.py ................ hand-written protobuf wire decoder (feed V3)
        +-- normalizer.py ........... protobuf bytes -> Tick (validated, quality-flagged)
        +-- candle_builder.py ....... CandleAggregator (1m) + resample (5m/15m)
        +-- recorder.py ............. SessionRecorder / RawFrameRecorder (no-clobber)
        +-- health.py ............... DataQualityMonitor -> connection state
        +-- ingestion_bridge.py ..... staging via the P2.2.10.1 registry
```

`config.py` holds `MarketDataConfig` (validated dataclass, `from_mapping`, `as_dict`),
`.env` loading, token masking (`redact`) and `MissingCredentials`.

### 3.1 Module responsibilities

| Module | Responsibility | Key guarantee |
| --- | --- | --- |
| `providers/base.py` | provider protocol, `SubscriptionMode`, `FeedLimits`, `MarketPhase`, `MarketStatusSnapshot` | a provider declares its own limits; the engine enforces them |
| `providers/upstox.py` | REST client (pacing, retry, cache, 401→`AuthenticationError`) and all endpoints | every request is read-only `GET` |
| `instruments.py` | expiry + option-chain discovery, ATM selection, strike window, futures, index, VIX | no key, expiry, strike or lot size is ever hardcoded |
| `proto.py` | Protobuf wire decoding for `FeedResponse` | malformed messages raise, never fabricate fields |
| `normalizer.py` | bytes → `Tick`; cumulative-volume differencing; OI baseline; OFO/duplicate detection | first sample never claims a volume delta |
| `candle_builder.py` | 1m aggregation + 5m/15m resample | session conventions inherited from `derivatives/` |
| `recorder.py` | session tree, tick parts, candle files, raw frame log, manifest | an existing artifact is never overwritten |
| `health.py` | state machine + per-instrument staleness/coverage | a dead feed cannot report healthy |
| `session.py` | IST session window, trading-day determination, stop conditions | local-clock results are always flagged `estimated` |
| `websocket.py` | connection lifecycle, subscriptions, reconnect, shutdown | limits enforced before connect |
| `service.py` | `status` / `discover` / `collect` / `validate` / `rebuild_candles` | meaningful exit codes |
| `ingestion_bridge.py` | stage recorded artifacts with provenance | refuses without a consent record |

## 7. Upstox endpoints integrated

All are read-only `GET`s. Base URL `https://api.upstox.com`.

| Purpose | Endpoint |
| --- | --- |
| Expiries + contract specs | `/v2/option/contract?instrument_key=…` |
| Live option chain (OI, IV, greeks, depth, prev OI) | `/v2/option/chain?instrument_key=…&expiry_date=…` |
| WebSocket authorisation | `/v3/feed/market-data-feed/authorize` |
| Exchange status | `/v2/market/status/{exchange}` |
| LTP snapshot | `/v3/market-quote/ltp?instrument_key=…` |
| Historical candles | `/v3/historical-candle/{key}/{unit}/{interval}/{to}/{from}` |
| Intraday candles | `/v3/historical-candle/intraday/{key}/{unit}/{interval}` |
| Instrument master (gz) | `https://assets.upstox.com/market-quote/instruments/exchange/complete.json.gz` |

`RestClient` centralises: minimum inter-request spacing, `429`/5xx exponential backoff
with jitter, per-URL TTL caching (option chain defaults to 900 s), `401` →
`AuthenticationError`, and token redaction in every message it raises.

## 8. Authentication

- Token source: `UPSTOX_ANALYTICS_TOKEN` from the process environment or `.env`
  (loaded by `config.load_env_file()`, which never overrides an existing variable).
- `.env` is already Git-ignored (`.gitignore` ignores `.env` and `.env.*` except
  `.env.example`); `.env.example` contains placeholders only.
- The token is printed **only as a mask** (`redact`), and `redact` is applied to every
  raised message, every log line and every CLI error path. A test asserts the raw token
  never appears in `str(exc)` for an auth failure.
- Expiry: the token payload's `exp` (when present) is decoded **without verification**
  purely to warn the owner ("N days remaining"); an expired token produces
  `AUTH_FAILED` + exit code 2 and a distinct status note.
- No password, OTP, PIN or TOTP flow exists anywhere in the code; no token is generated,
  refreshed or revoked by this code (one active token per account is the owner's
  responsibility).
- Consent for staging is a separate, independent gate (`MARKET_DATA_CONSENT_RECORD` or
  `--consent-record`).

## 9. WebSocket subscription design

1. `GET /v3/feed/market-data-feed/authorize` → one-time `wss://` URI (authorized per
   connection; re-fetched on every reconnect so a rotated token is picked up).
2. Binary frames → `proto.decode_feed_response`; text frames → JSON control messages
   (`market_info`, errors). A text `{"type":"error", ...}` with a 401/403 marker moves the
   monitor to `AUTH_FAILED` instead of retrying forever.
3. Subscriptions are **grouped by the cheapest sufficient mode** and sent as one
   `sub` message per group:
   - index / VIX → `ltpc`
   - futures → `full_d30` when available, else `full`
   - options → `option_greeks` (ltp + greeks + OI, cheapest mode carrying OI)
4. `enforce_subscription_limits` runs **before** connecting and raises rather than
   sending an over-limit subscription. Unused capability limits are not consumed: full
   mode stays well under 1,500, `ltpc` under 2,000, `option_greeks` under 2,000.
5. Reconnect: `_FeedClosed` → `mark_disconnected` → exponential backoff
   `base * 2^(n-1)` with jitter, capped (`ws_backoff_max_seconds`, default 60 s) →
   re-authorise → reconnect → **resubscribe the full set** → `mark_connected`.
   `ws_max_attempts` (0 = unlimited) bounds it; exhaustion records
   `giving up after N reconnect(s)` as the stop reason.
6. Heartbeat: `_recv` uses a socket timeout; silence beyond
   `ws_stale_seconds` moves the monitor to `STALE` while the socket is still open, which
   is different from `DISCONNECTED`.
7. Shutdown: `SIGINT`/`stop_event`/session close → stop subscribing, drain, flush ticks,
   write candles + manifest, close the socket. KeyboardInterrupt is caught in the CLI
   (exit 4) after the recorder has flushed.

## 10. Instrument coverage (dynamic, per session)

`InstrumentDiscovery` produces an `InstrumentUniverse`:

1. **Expiries** from `/v2/option/contract` (never a hardcoded date), filtered to
   `expiry_offsets` (default `(0,)` = nearest).
2. **Option chain** for each expiry → rows with `strike`, `option_type`, `oi`, `prev_oi`,
   `iv`, greeks, depth.
3. **ATM** = chain strike nearest the index LTP (or chain spot when LTP is unavailable).
4. **Strike window**: `strikes_below_atm` .. `strikes_above_atm` (default ±2 → 10 legs
   per expiry), each leg's `instrument_key` taken from the chain response.
5. **Index** (`NSE_INDEX|Nifty 50`) and **India VIX** (`NSE_INDEX|India VIX`) from
   config, present only if the instrument master knows the key.
6. **Futures**: nearest NIFTY future found in the instrument master by name/exchange,
   not by a hardcoded key or expiry.
7. Lot size and contract specs are carried through from the provider where present and
   never invented.

`instrument_key`, `expiry`, `strike`, `option_type` and `trading_symbol` are preserved
verbatim on every tick and candle.

## 11. Data schema

### 11.1 Normalised tick (Parquet, one row per observation)

`instrument_key, trading_symbol, underlying, kind, expiry, strike, option_type,
exchange_ts_ms, local_ts_ms, ltp, ltq, close_price, volume_cumulative, open_interest,
open_interest_previous, iv, bid_price, bid_qty, ask_price, ask_qty, depth_levels,
delta, theta, gamma, vega, rho, source_provider, subscription_mode, sequence, quality,
quality_flags`

Two timestamps are always present and never conflated: `exchange_ts_ms` (provider) and
`local_ts_ms` (receive).

### 11.2 Option-chain row

`instrument_key, expiry, strike, option_type, ltp, close_price, volume, oi, prev_oi,
bid_price, bid_qty, ask_price, ask_qty, delta, theta, gamma, vega, rho, iv`

`prev_oi` seeds `TickNormalizer.set_previous_open_interest`, so the first tick already
has a valid OI-change baseline instead of a bogus one.

### 11.3 Candle row

`instrument_key, trading_symbol, underlying, kind, expiry, strike, option_type,
timeframe_minutes, candle_open, candle_close, open, high, low, close, volume, n_ticks,
open_interest, open_interest_previous, oi_is_last_observation, volume_basis,
volume_complete, is_complete, first_tick_ts_ms, last_tick_ts_ms, source_provider,
candle_origin, quality_flags`

`candle_origin = 'locally_aggregated'` for everything this engine produces, so a
consumer can never mistake it for provider OHLC. Provider historical candles are fetched
through `get_historical_candles`/`get_intraday_candles` and keep their own origin.

### 11.4 Manifest (`manifest.json`, per session)

`session_id, provider, session_date, started_at, ended_at, state, tick_rows,
frames_recorded, decode_failures, reconnects, universe{subscriptions, by_mode, expiries,
atm_strike}, candle_files, quality_counts, config (redacted), app_version`.

## 12. Storage locations

```
data/live/<provider>/<YYYY-MM-DD>/<session_id>/
    manifest.json                 session summary + universe + quality counts
    raw/frames.jsonl              one JSON object per received frame (append-only)
    ticks/part-0001.parquet       normalised ticks, one file per flush
    candles/1m/candles.parquet
    candles/5m/candles.parquet
    candles/15m/candles.parquet
    rebuilt/…                     only with `candles --write`
data/live/<provider>/last_run.json   status view (atomic replace)
```

Write rules (`recorder.py`):

- Every recorded artifact is written to a temporary file in the same directory and then
  published with `os.link` — an existing destination raises `RecordingError
  ("refusing to overwrite")`. Sessions are never reused; a second session on the same
  day gets its own `session_id` directory.
- The **only** files ever replaced are status views (`last_run.json`) and the per-session
  `manifest.json` (rewritten on close), because they are derived summaries, not market
  data.
- Tick flushes are bounded by `flush_every_ticks` (default 200), so a crash loses at most
  that many rows.
- Raw frames are opt-in for staging (`session_artifacts(include_raw=...)`) because they
  are large; they are always recorded locally for replay and debugging.

## 13. Candle aggregation design

- **1m**: `CandleAggregator(1)` buckets ticks by *exchange* time into the repository's
  left-edge convention `[T, T+1)`; the 15:30 closing print folds into the 15:29 bucket,
  exactly as `derivatives/candles.py` does. 375 buckets per session; no bucket is created
  without a tick.
- **5m / 15m**: `resample(candles, minutes)` regroups the 1m frame per instrument.
  `open` = first 1m open, `high`/`low` = extremes, `close` = last 1m close, `volume` =
  sum with `min_count=1` (so "unavailable" never silently becomes 0), `n_ticks` = sum,
  `is_complete` = all constituent 1m buckets complete.
- **Volume**: WebSocket `vtt` is *cumulative*. The normalizer differences it per
  instrument. The first observation only sets a baseline and yields **no** delta
  (`volume_complete=False` on the first candle). A counter decrease is treated as a
  reset: the new cumulative value becomes the delta and the candle is flagged
  `volume_counter_reset`. When the provider supplies no volume at all, the candle gets
  `volume_basis='unavailable'` and `volume=None` — never 0.
- **Open interest**: absolute OI is sampled (last observation in the bucket wins) and
  flagged `oi_is_last_observation`; it is never summed.
- **No fabricated intervals**: a minute with no ticks produces no candle. The validator
  reports the missing buckets (`gaps`) instead of filling them.
- `rebuild_candles` recomputes 1m/5m/15m from a recording and cross-checks the row and
  tick counts against the files written live (regression guard for the aggregator).

## 14. Rate-limit controls

- Minimum spacing between REST requests, enforced centrally in `RestClient`.
- Exponential backoff with jitter on `429` and 5xx, bounded retries, `Retry-After`
  honoured when present.
- Per-URL TTL cache: the option chain is fetched **once per expiry per session**
  (`chain_cache_seconds=900` by default), never polled per tick.
- Live prices come from the WebSocket, not from polling `/v3/market-quote/ltp`.
- Instrument master is cached on disk with an age check
  (`instrument_master_max_age_hours=24`).
- Auth failures (`401`) are not retried — they surface immediately as `AUTH_FAILED`.
- Feed limits are enforced before connecting, so a limit violation never costs a
  connection.

## 15. Health states and data quality

`health.py` exposes exactly the required vocabulary:

`CONNECTED · DISCONNECTED · RECONNECTING · STALE · DEGRADED · AUTH_FAILED ·
SESSION_CLOSED`

- `STALE` — socket open but no frame for `ws_stale_seconds`.
- `DEGRADED` — connected, but ≥1 subscribed instrument has never printed, or the share of
  non-`CLEAN` ticks exceeds the threshold.
- `AUTH_FAILED` — 401 on REST or an auth error frame; never auto-recovers silently.
- `SESSION_CLOSED` — the session manager says the day is over.
- Per-tick quality flags: `CLEAN, NO_LTP, NO_TIMESTAMP, OUT_OF_ORDER, DUPLICATE,
  UNKNOWN_INSTRUMENT, OFF_SESSION, PRICE_JUMP, NO_VOLUME, NO_OI, EXPIRED_CONTRACT`.
- `coverage` = subscribed instruments seen / subscribed.
- `bad_quality_share` is reported so a run with 40 % `OUT_OF_ORDER` cannot look healthy.

`sla`: a disconnect never resets `instruments_missing`; a reconnect resubscribes every
instrument and the monitor only clears `STALE` after a fresh frame.

## 17. Integration with the ingestion foundation

`ingestion_bridge.publish_session(session_dir, config)`:

1. Requires a consent record, else `PermissionError` — the data-use gate is not
   bypassable by a flag default.
2. Copies artifacts into a work directory under `session_id__<name>` aliases (two
   sessions on one day must not collide on `part-0001.parquet`).
3. Calls `registry.register_file(...)` per artifact with
   `domain_id=<configured>`, `source_id=<provider>-<date>-<session>`,
   `axis2_permission_status='CONDITIONAL_PERSONAL_RESEARCH'`,
   `axis1_status='PASS_WITH_LOGIN'`, and the consent record attached.
4. Returns `{count, published[{artifact, sha256}], source_id,
   axis2_permission_status}`; every staged artifact has a provenance sidecar and a
   SHA-256.

Curated promotion remains a manual owner action through the existing registry.

## 18. CLI reference

```
python -m nifty_quant.market_data status      [--json] [--data-root PATH]
python -m nifty_quant.market_data instruments [--strikes-above N] [--strikes-below N]
                                              [--expiry-offsets 0 1] [--no-futures]
                                              [--no-vix] [--verbose] [--json]
python -m nifty_quant.market_data collect     [--max-seconds S] [--force] [--publish]
                                              [--wait-for-open] [--max-wait-seconds S]
                                              [--consent-record TEXT] [--json]
python -m nifty_quant.market_data validate    [--session DIR] [--json]
python -m nifty_quant.market_data candles     [--session DIR] [--write] [--json]
```

Exit codes: `0` ok · `2` credential missing/expired · `3` auth rejected or data invalid ·
`4` market closed / session ended / interrupted.

`status` reports: provider, data root, token (masked) and days remaining, IST now, the
session window, market phase, whether today is a trading day **and why**, whether that
answer is estimated, last-run state, subscription count, instruments seen, latest tick,
last frame, missing/stale counts, last error and the latest session directory.

`--force` bypasses the session-stop check for the whole run (otherwise a run started
outside the window exits after one iteration) and is reported in the manifest so a
forced run is visible afterwards.

## 24. KNOWN LIMITATIONS

1. **Directional/relative volume only until the second tick.** The first observation of
   each instrument establishes a baseline; the first candle of the day carries
   `volume_complete=False`. No attempt is made to guess the pre-open volume.
2. **Depth is summarised.** `depth_levels` records how many levels arrived and the best
   bid/ask price and quantity are columns; the full 5-level ladder is not persisted per
   tick (raw frames still contain it).
3. **One connection per session.** No `d30` second connection, so full-mode capacity is
   not exploited; conservative by choice.
4. **Trading-day calendar ends 2026-11-03.** Beyond it the code falls back to a weekday
   guess and marks it `estimated=True`; it will not claim authority for 2027 holidays.
   The calendar should be refreshed before it goes stale.
5. **`exp` parsing depends on the token carrying a standard `exp` claim.** If Upstox
   omits it, expiry shows as `unknown` rather than failing.
6. **Raw frame log is uncompressed JSONL** — large on a busy session (hundreds of MB).
   It is excluded from staging by default.
7. **`rebuild_candles` needs the full tick set**; a session whose tick parts were manually
   pruned cannot be rebuilt (it reports the shortfall instead of guessing).
8. **`ws_max_attempts=0` (unlimited) is the production default** — a permanently dead
   feed retries at the 60 s cap forever unless `--max-seconds` or the session end stops
   it. This is intentional for unattended collection, but it means "no data" is signalled
   by `STALE`/`DISCONNECTED` in the status view, not by process exit.
9. **Windows Task Scheduler autostart is documented, not installed.** No scheduled task
   was created on this machine.

## 25. Instructions for the owner

### 25.1 Configure the Analytics Token (the only blocking step)

1. Get a token: Upstox Developer API → **Analytics Token**
   (`https://upstox.com/developer/api-documentation/analytics-token/`). It is free,
   read-only, valid one year, needs no static IP, and cannot trade. Only **one active
   token per account** exists, so generating a new one invalidates the old one.
2. In the repository root:

   ```bat
   copy .env.example .env
   ```

3. Open `.env` and replace the placeholder:

   ```
   UPSTOX_ANALYTICS_TOKEN=eyJ...your-real-token...
   ```

   Optionally set `MARKET_DATA_CONSENT_RECORD=...` for staging.
4. Confirm `.env` is ignored (it is, by `.gitignore`); never commit it and never paste
   the token into a chat, issue or log.
5. Verify:

   ```bat
   python -m nifty_quant.market_data status
   ```

   Expect `token : eyJ…abcd (configured)` and exit code 0. Then:

   ```bat
   python -m nifty_quant.market_data instruments --verbose
   ```

   which performs the **first real authenticated call** and prints the discovered
   universe (expiries, ATM, strikes, subscription count by mode).

### 25.2 Start collection

Manual, during market hours:

```bat
python -m nifty_quant.market_data collect
```

Before the open, with waiting:

```bat
python -m nifty_quant.market_data collect --wait-for-open
```

Bounded smoke test (recommended as the first live run):

```bat
python -m nifty_quant.market_data collect --max-seconds 120 --strikes-above 1 --strikes-below 1
```

Collect and stage into the ingestion foundation in one step:

```bat
python -m nifty_quant.market_data collect --publish --consent-record "private non-commercial research"
```

### 25.3 Stop collection

- Foreground: **Ctrl+C**. The recorder flushes buffered ticks, writes candles and the
  manifest, then exits with code 4. Partial data is kept.
- `--max-seconds N` stops itself.
- It also stops by itself after the 15:30 close plus grace, or if the day is not a
  trading day.

### 25.4 Inspect and validate a session

```bat
python -m nifty_quant.market_data status
python -m nifty_quant.market_data validate --session data\live\upstox\2026-11-09\<session_id>
python -m nifty_quant.market_data candles  --session data\live\upstox\2026-11-09\<session_id> --write
```

`validate` exits 3 on a fatal invariant failure; `candles` rebuilds 1m/5m/15m from the
ticks and cross-checks the counts.

### 25.5 Optional: autostart on this Windows host

The process cannot collect while the machine is off or asleep. To start it before the
open, create a Task Scheduler task (do **not** use a service — it needs the user's
profile and network):

```

Arguments: -m nifty_quant.market_data collect --wait-for-open
Start in:  D:\Downloads\nifty_quantum
Trigger:   Monday-Friday 08:45
Settings:  "Stop the task if it runs longer than 8 hours"; "Do not start a new instance"
```
