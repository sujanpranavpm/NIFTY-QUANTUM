# P2.2.3.1 — Final Independent Audit of the Options-Buying Adapter

Scope: an independent audit of the P2.2.3 adapter (`nifty_quant/options/`) before
approval. Every figure was **recomputed for this audit**, largely *independently of the
adapter's own helpers* (the DTE ladder was rebuilt from raw parquet, cost labels were
re-derived through the commission, the signal count was re-tallied from the strategies).
The audit script is `scripts/_p2231_audit.py`; its full output is `logs/_p2231_audit.log`.

Verdict: **all eight checks PASS. No defects found. No blockers to approval.** Three
items are recorded as honest *limitations* (not bugs) in §B. No strategy, engine, or cost
file was modified by this audit; the only new files are the audit script, this report, and
the log. **Nothing is committed. No strategy optimisation was begun.**

## A. Findings by check

### Check 1 — No lookahead  ·  PASS

Decision data at the option trade is exactly what is knowable at the **close of the
signal session D**:

- Direction (`CE`) and the spot reference are the strategy's `flat→long` state and the
  **D-close index value** (`DailySignal.spot = closes.loc[D]`) — `signals.py`.
- Strike target = `round(spot / interval) × interval`, computed from **D-close spot** and
  the **effective-dated** strike interval in force on `entry_day` (a public contract spec,
  not a price) — `selection.py`.
- D+1 is used **only** for permitted entry/execution checks: (i) *which* expiries/strikes
  actually printed a bar on the D+1 session (tradability), and (ii) the entry fill price =
  **D+1 first-bar open** via the engine's next-bar rule (`bars.py`,
  `options_execution.py:195`).

The audit found **no use of any D+1 (or later) price/high/low/close to make the
directional or contract decision**. `git diff` on tracked code is empty, confirming the
strategies are called unchanged through `run_backtest` (which is itself next-bar, so the
D position reflects data through D close only).

### Check 2 — Timestamp mapping D → next eligible 15m session at D+1  ·  PASS

Independently verified on all 39 executed trades against the raw index-session ruler:

```
entry == immediate next index session after signal : 39 / 39
same-day entries                                   : 0
entries NOT the immediate next session             : 0
signal_dates that are index sessions               : 39 / 39 (True)
```

`entry_index` is the first 15m bar whose `trading_day == D+1` and `signal_index =
entry_index − 1` (a real earlier bar) — mapping is on **timestamps, not integer indices**.
If the option did not print on D+1, the signal is rejected (`NO_OPTION_BARS_ON_ENTRY`),
never deferred to a later session and never fabricated.

The DTE ladder was recomputed from raw parquet on the **index-session ruler**

**Reconciliation with previous coverage reports** (`P2.2.2.1_METHODOLOGY_RECONCILIATION.md`

holdout**. Only **13 of the 121** calendar-eligible days are actually executable — see §B.

### Check 4 — Liquidity (share-equivalent volumes; gate does not imply fills)  ·  PASS

The conservative floor is unit-aware and equals `lot_size × lots` share-equivalents for
every lot size seen (`lots = 1`):

| Effective board lot | A_OPTIMISTIC floor | B_BASELINE floor | C_CONSERVATIVE floor |
|---:|---:|---:|---:|
| 25 | 0.0 | 0.0 | **25** |
| 50 | 0.0 | 0.0 | **50** |
| 65 | 0.0 | 0.0 | **65** |
| 75 | 0.0 | 0.0 | **75** |

`conservative_equals_lot_size_x_lots = True`. Bar `volume` is in the same share-equivalent
units (provider `volume = contracts × board lot`, conserved 1m→5m→15m). The engine gate
(`options_execution.py:256`) is **exit-only and fail-closed**: below the floor the *exit* is
refused and the position stays open (→ `OPEN_AT_END` / `UNRESOLVED`); it **never blocks
entry** and **never guarantees a fill**. The audit confirms a `FILLED` row therefore does
**not** attest that entry was liquid (see §B, Limitation 2).

## B. Limitations (honest findings, not defects — no action blocks approval)

1. **Statistically under-powered.** Only **13** of the 121 eligible calendar-days are
   executable (≤ a handful of trades per candidate), and **116 / 127** rejections are
   `NO_OPTION_BARS_ON_ENTRY` — the assembled option data does not print a tradable contract
   on most signal days. This matches the pre-registered expectation of **"insufficient
   evidence"**; it is a property of the data, not a bug. **No winners may be declared.**
2. **The conservative liquidity gate is currently non-binding.** At `lot_size × lots`
   floors (25–75 share-equivalents) versus typical 15m bar volumes in the **thousands**, the
   exit gate rejects nothing in this dataset. A `FILLED` under `C_CONSERVATIVE` therefore
   does **not** demonstrate real-world fillability; the slippage bps (0/2/5) remain
   *estimated haircuts, not observed execution cost*. Reported as such.
3. **PE is never exercised by these five strategies.** All Tier-1 candidates are
   `long_only`, so only `CE` signals occur (`option_type` CE on 39/39). PE selection is
   implemented and unit-tested, but these strategies do not generate short signals — a
   property of the strategies, recorded honestly rather than manufactured.
