# P2.2.1 — Strategy Inventory (as built)

Date: 2026-11-06 · Baseline commit: `03a5d27` (clean) · Budget: ₹0

Scope: an evidence-based inventory of the **20 registered order-based strategies** in
`nifty_quant/strategies/`, read from their actual `_compute_orders` implementations,
`SPEC` metadata, `DEFAULT_PARAMS`, the shared engine, and the on-disk datasets. This is an
**audit only** — no strategy logic was modified, no parameters were tuned, and **no strategy
is claimed to be profitable**. Classification and screening recommendations live in
`P2.2_STRATEGY_CLASSIFICATION.md`.

---

## 0. Global facts that apply to every strategy

These come from shared code, not from any single strategy, and they constrain every entry
below.

### 0.1 What the strategies actually trade
All 20 are ports of the `quantjourney-bt` order-mode examples (`orders_01`…`orders_20`,
upstream file order preserved). Sixteen of them run **per cash-equity constituent** of the
NIFTY 50 in an own capital sleeve (`run_mode="per_stock"`); `orders_17` runs cross-sectionally
over the whole universe (`run_mode="portfolio"`); `orders_19`/`orders_20` are the two FX /
futures examples that are **not applicable to NSE equity** (`applicable_to_nse_equity=False`,
registry `excluded_ids()`).

**None of the 20 strategies places an option order.** Each submits `Order(instrument, …)`
where `instrument` is an equity/FX/futures symbol. A repository-wide search of the strategy
package for `premium`, `strike`, `expiry`, `option_type`, `lot_size`, `CE`/`PE`,
`IndiaOptions*`, `options_costs` returns matches only inside the two `ContractSpec` FX/futures
examples — never an index-option contract. The index-option **cost** model
(`IndiaOptionsCosts`, `nifty_quant/engine/options_costs.py`) and the 1m/5m/15m NIFTY **option**
candle datasets exist in the project, but no strategy consumes them. So today these are
**underlying-instrument strategies**, not option-buying strategies.

### 0.2 Execution / fill model (anti-look-ahead contract)
From `nifty_quant/engine/fill_engine.py` and `EngineConfig` (`config.py`):

* **Next-bar semantics** — an order raised after bar *t* closes can only fill on bar *t+1*.
  This is the system's single most important no-look-ahead property.
* **Open fills** (`fill_at="open"`) — market orders fill at `bar.open`; the slippage model sees
  only the *previous* bar's HLCV, because the current bar's high/low/close are not observable
  at its open.
* **Priority** — stops before limits before markets; when a protective stop and a take-profit
  are both reachable inside one bar, **the stop wins** (conservative for a long position).
* **Gaps** — a stop that gaps through fills at the worse open, never at the stop price.
* **Brackets** — a `BRACKET` order decomposes into an entry plus an OCO (take-profit, stop-loss)
  pair activated on the first entry fill.

Signals are computed from panels indexed by bar date and prior-bar rolling windows
(`sma.loc[date]`, `close.iloc[idx-lookback : idx]`, persisted `_prev_signal`), so no strategy
reads the current or a future bar's close to decide the current bar. `tests/test_lookahead_guards.py`
and `tests/test_reproducibility.py` exist to enforce this.

### 0.3 Data actually available (evidence, not assumption)
* **Daily**: `ResearchConfig.intervals = ("1d",)`, `universe = "NIFTY50"` (51 constituents),
  benchmark `^NSEI`. The daily cache currently holds only a **smoke subset** (HDFCBANK, INFY,
  RELIANCE, TCS, M_M, and the `IDX_NSEI` index); the **full-universe daily fetch is outstanding
  (T10)**. Indicators available: `SMA`, `RSI` (Wilder and SMA variants), `true_range`/`ATR`
  (`nifty_quant/indicators.py`); Donchian and momentum are computed inline from `adj_close`.
* **Intraday**: `data/derived/candles/` holds **1m / 5m / 15m NIFTY *option* premium candles**
  (per expiry; columns `timestamp, trading_day, symbol, expiry, strike, option_type, OHLCV,
  open_interest`), produced by `scripts/_p2_generate_candles.py`. There are **no 1m/5m/15m
  underlying-index or constituent-equity candles** on disk, and **no 30m grid at any resolution**.
* Consequence: the daily strategies could run once T10 completes; the two intraday strategies
  (`orders_15` 5m, `orders_16` 30m) have **no matching underlying data** in the repo today, and
  the option-premium intraday data is not wired to any strategy.

### 0.4 Cost & validation limitations carried into this audit
* The options readiness gate `transaction_costs_verified` is **fail-closed** (2 slab-era
  `exchange_txn` rows stay `estimated`); strict financial validation of option round trips is
  still blocked, so any option-oriented work remains research-modelling only.
* Signals are emitted only through `nifty_quant/signals/gating.py`, which approves a strategy
  solely on a validation verdict of `supported` plus `enough_trades`/`oos_profitable`/strict-split
  agreement — **never** on an in-sample profit claim. No strategy has been validated here.
* `orders_17` uses a **current, not point-in-time, NIFTY 50 membership snapshot**, so it carries
  a documented survivorship path (reported, not corrected).

### orders_01 — Market SMA Crossover
1. **Logic / underlying idea.** Trend-following; long-only SMA(20)×SMA(50) crossover on adjusted
   close of each cash-equity constituent. Upstream `example_orders_01_market_sma_cross.py`.
2. **Indicators / input data.** `SMA_20_close`, `SMA_50_close`, `adj_close`, daily OHLCV.
3. **Entry.** `signal=1` (fast>slow) on a flat→long flip, position flat, no pending order →
   MARKET buy sized `nav × weight(0.18) / close`.
4. **Stop / target.** **None.** Exit only on the reverse cross (fast<slow) → MARKET sell full.
5. **Timeframe / holding.** `1d`; multi-week/hold-until-cross (time in trade, no fixed horizon).
6. **CE/PE-option-buying suitable?** Not as-is — trades the constituent equity, no premium/strike.
   Directional (long bias) signal, so it is a *retarget candidate* (see classification).
7. **Instrument worked on.** NIFTY50 constituent equity OHLC (not the index, not the premium).
8. **1m/5m/15m compatibility.** Designed for `1d`. On 1m/5m/15m the SMA20/50 window would mean
   minutes, not days — changes the strategy; underlying intraday data also absent. Not applicable.
9. **Look-ahead / repainting / leakage.** Clean: cross from `loc[date]`, persisted `_prev_signal`,
   next-bar fill. No leakage.
10. **Missing data / limitations.** Needs full-universe daily fetch (T10). No risk control other
    than the cross, so max adverse excursion is unbounded — matters more under option leverage.

### orders_02 — Market RSI Mean Reversion

9. **Look-ahead.** Clean (`loc[date]`, next-bar fill).
10. **Missing / limits.** T10 daily fetch. Vendor RSI not published → Wilder substitution
    documented; threshold-cross timing sensitive to RSI variant. Unbounded MAE (no stop).
